Ejecutá la automatización editorial de CinePosta en Clovhis/sucuplecuc usando el entorno cloud guardado y únicamente la cuenta y cuotas incluidas de ChatGPT. No uses OpenAI API, claves de LLM, sesiones exportadas ni credenciales de una PC; no compres créditos. La API oficial de Buffer usa sólo la integración existente. Si falta checkout, cloná con el acceso GitHub oficial del entorno; actualizá desde origin/main conservando trabajo previo. Si falta acceso oficial, detenete sin copiar credenciales.

Leé AGENTS.md, skills/cineposta-cloud-nota-diaria/SKILL.md y su references/editorial-quality.md. Reutilizá cineposta-editorial. El orquestador prepara, congela, registra las ejecuciones reales y valida/publica; no investiga, redacta ni sustituye al revisor. Priorizá exactitud y utilidad para lectores argentinos sobre la duración. No hagas aprendizaje continuo ni auditoría del catálogo.

Enumerá los modelos Luna y razonamientos anunciados por collaboration.spawn_agent en este run, sin inventar IDs, y guardá observedAt/models en .tmp/cineposta-daily/native-catalog.json. Ejecutá node scripts/daily-editorial.mjs --prepare. Si ya existe registro del día con revisión vigente, usá --publish para verificar Pages y recuperar Buffer idempotentemente; terminá sin otra nota ni otra redacción. Los dos recibos históricos sin revisión sólo admiten --verify: su excepción no habilita nuevos envíos a X; no reenvíes esos tweets.

Para una preparación nueva, usá la selección impresa como argumentos reales model y reasoning_effort de exactamente DOS agentes nativos distintos, fork_turns none: autor y revisor factual independiente. Probá mínimamente cada ejecutor y reutilizalo para su rol. Si falta la última Luna, Max, cuota o el segundo ejecutor, bloqueá; no cambies familia ni uses CLI/API para inferencia. No marques completed una llamada fallida.

El autor prepara la nota, sus WebP inspeccionados y draft.json con tweet original, claims con evidencia por afirmación, acceso desde Argentina y derechos por imagen conforme al contrato. Revisa nombres, cantidades/unidades originales y conversiones, fechas/zonas, lugares, citas, eventos y disponibilidad. Una copia de un comunicado no cuenta como corroboración independiente; sin otra fuente real, atribuir y limitar, nunca inventarla. Cuando aplique explicar cómo verlo: enlace oficial directo público, ventana/horario ART, costo confirmado, territorio y subtítulos; declarar lo no confirmado y las excepciones por título. Verificar condiciones/titulares antes de incorporar imágenes: origen no es licencia, y la portada necesita permiso para web y redes con créditos/enlaces exigidos. Elegir alternativas autorizadas o bloquear ante dudas. No contactar titulares automáticamente. El mismo autor redacta el tweet original con comentario específico, URL directa y 1–3 hashtags, sin otra invocación creativa. Autor/revisor no crean agentes, no editan scripts/config, no hacen commits ni publican.

Tras completion real del autor guardá native-execution.json con provider codex-native, ID/model/effort reales, probe passed, status completed y forkTurns none. Ejecutá --review: congela texto, tweet, evidencia y bytes visuales e imprime el digest y las rutas del snapshot/informe/ejecución del revisor. Encargá al segundo agente abrir las fuentes por su cuenta y auditar todo el snapshot y el historial, incluyendo tweet, datos para Argentina, linaje de fuentes y condiciones visuales. Sólo escribe factual-review.json, no corrige el contenido ni se aprueba con tests técnicos. El orquestador registra el completion real del revisor en native-review-execution.json, con otro agentId y la misma selección Luna/Max.

Con contradicciones materiales, claims sin verificar o derechos sin resolver NO hay commit ni push. Conservá el informe adverso, devolvé hallazgos al mismo autor, ejecutá --review sobre la preparación corregida y pedí nueva revisión al mismo revisor. No borrar el journal ni omitir IDs materiales: documentar antes/después/evidencia de cada corrección y resolverlos expresamente. Si el gate detecta una contradicción que el revisor omitió, éste debe registrarla y comprobar la corrección. No aprobar sólo porque pasaron Astro, Playwright o formatos. Cualquier cambio de texto/tweet/evidencia/imágenes invalida la aprobación; no uses un hash de otra preparación.

Con revisión independiente vigente ejecutá --dry-run y --publish sobre la misma preparación. Si main cambió, --revalidate antes de reintentar; si cambió el contenido revisado, --review y nueva revisión antes. No regenerar otra nota para eludir un bloqueo. Exigí verificación Pages y URL pública antes de informar éxito. Si falla sólo Pages, revisá logs/anotaciones; ante error transitorio de GitHub reintentá una vez deploy.yml sobre main (rerun o workflow_dispatch si rechaza rerun), sin otra nota/commit. Luego --publish recupera verificación y Buffer idempotentemente; --verify sólo comprueba Pages.

Después de Pages y URL accesible, --publish envía el tweet por el workflow Buffer existente, shareNow inmediato, con verificación de @cineposta y deduplicación. Si falla Buffer conservá la nota y reintentá sólo --tweet; no regeneres contenido ni envíes por otra vía. No modifiques agendas, automatizaciones semanales ni el flujo de Buffer. Reportá modelo/Max reales de autor y revisor, URL y resultado o bloqueo concreto, sin activar servicios facturables.
